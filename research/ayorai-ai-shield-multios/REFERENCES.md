# AYORAI AI Shield — Reference Map

This research track uses external sources as design references. They are not certifications of AYORAI.

## Threat-informed references

- NIST Cybersecurity Framework 2.0: https://www.nist.gov/cyberframework
- MITRE ATT&CK: https://www.mitre.org/focus-areas/cybersecurity/mitre-attack
- MITRE ATT&CK Evaluations: https://www.mitre.org/news-insights/impact-story/mitre-attck-evaluations-indispensable-resource-global-cyber-defenders
- OWASP Top 10 for LLM Applications: https://owasp.github.io/www-project-top-10-for-large-language-model-applications/
- MITRE ATLAS: https://atlas.mitre.org/

## Independent security testing references

- AV-TEST: https://www.av-test.org/
- AV-TEST current antivirus tests: https://www.av-test.org/en/antivirus/
- AV-Comparatives latest tests: https://av-comparatives.org/latest-tests/
- AV-Comparatives business security tests: https://av-comparatives.org/testmethod/business-security-tests-and-reviews/

## Competitive architecture references

The research also studies public product architecture and security documentation from major vendors such as Microsoft, CrowdStrike, Palo Alto Networks, SentinelOne and ESET.

These vendors are reference points for capabilities and operational patterns, not claims of equivalence or superiority.

## Reference governance

Every external reference incorporated into the project should record:
- source;
- URL;
- retrieval date;
- relevant version;
- scope;
- what was learned;
- what AYORAI implemented;
- what remains unverified.

External evidence must remain distinguishable from AYORAI-generated benchmark evidence.
