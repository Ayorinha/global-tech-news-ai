# Contributing

Thank you for contributing. Small, focused, reproducible changes are preferred over large rewrites.

## Good contribution areas
- bug fixes and regression tests
- documentation and examples
- evaluation and benchmark fixtures
- security and reliability improvements
- developer experience, CI and observability

## Workflow
1. Fork the repository and create a focused branch.
2. Keep changes scoped and explain the rationale.
3. Run the project's documented tests and checks.
4. Use synthetic/public data only; never commit credentials, secrets, personal or confidential data.
5. Open a pull request using the repository template.

PRs should include reproducible validation evidence and update documentation when behavior changes.
